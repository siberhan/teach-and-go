Teach&Go — App Map

A take-home guide to where things live. Snapshot of commit d7aa97f; the code may drift after this.

What the app does. A private tutor records a lesson in the browser. The AI turns the recording into “where you stopped” and what to do next time, against the plan built from the curriculum. A voice assistant (a small agent) can create, rename, plan and delete spaces on every screen. There is no server: data lives in the browser (IndexedDB via Dexie), AI calls go straight to OpenRouter (and Groq for speech, if its key is set).

The route (3 stops)

  1. Input — src/components/AgentChat.tsx, search finishListening. The mic recording becomes text with dictate(), then handle() sends it, plus any attached documents, to the agent. The same component is the assistant panel and the plan conversation.
  2. Logic — src/lib/agent.ts, search runAgent and create_space. One generateText call from the Vercel AI SDK lets the model call tools up to MAX_STEPS times. Each tool is a small function with a zod schema; the instructions hold the rules (never guess the routine, ask for a name, delete only after a tap).
  3. Storage and result — src/lib/db.ts (the Space type) and src/screens/Spaces.tsx (search useLiveQuery). The tool writes to IndexedDB; every screen that reads with useLiveQuery re-renders by itself. That is why the new space appears without navigating.

To change this, start here

  • What the assistant may do — add or edit a tool({...}) in src/lib/agent.ts.
  • How the AI plans — the planRules text in src/lib/agent.ts.
  • The lesson summary (“where you stopped”) — analyzeLesson in src/lib/ai.ts, called from src/lib/analysis.ts.
  • The model — llm.model in src/lib/openrouter.ts.
  • Speech provider order — speechToText in src/lib/speech.ts.
  • Colors and type — the tokens at the top of src/styles/global.css.

A practice to reuse

Turn a reported bug into a check before trusting the fix. When “no lesson this week, we start next week” got the reply “noted” but nothing was saved, the fix was not only a new prompt rule: scripts/check-setup.mjs now sends that exact sentence and asserts that the routine's start date moved and the lesson days stayed the same.

On another project: whenever an AI says it did something, check the stored result, not the reply text.

Run it again

npm install then npm run dev, open the printed address, and add your OpenRouter key (and optionally a Groq key) in Settings.
Checks

node scripts/check-setup.mjs, check-kernel.mjs, check-assistant.mjs drive the real app in a browser with real AI calls; they read keys from the git-ignored .env.local.
